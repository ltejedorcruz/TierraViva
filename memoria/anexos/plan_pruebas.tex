\chapter{Plan de pruebas}
\label{anexo:plan_pruebas}

Este anexo define el plan de pruebas seguido para validar el funcionamiento de TierraViva. El objetivo es comprobar de forma progresiva cada parte del sistema antes de realizar una integración completa: sensores, comunicaciones, almacenamiento, \textit{dashboard} y actuación sobre el riego.

Al tratarse de un prototipo que combina hardware, software y servicios externos, las pruebas se han organizado por fases. Esta estrategia reduce el riesgo de errores difíciles de aislar, ya que permite validar primero cada bloque por separado y después comprobar el comportamiento del sistema completo.

\section{Estrategia general de pruebas}

La validación de TierraViva se plantea como un proceso incremental. En primer lugar se prueban los componentes de forma aislada; después se comprueba la comunicación entre bloques; finalmente se valida el funcionamiento integrado del prototipo.

\subsection{P17. Prueba funcional en entorno real en Agrolab Móstoles}
\label{subsec:p17_agrolab_mostoles}

\textbf{Objetivo.} Validar el comportamiento del prototipo TierraViva en un entorno real de cultivo, comprobando adquisición de datos, publicación de telemetría, supervisión desde Raspberry Pi, visualización en \textit{dashboard} y actuación controlada del riego.

\textbf{Entorno de prueba.} La prueba se realiza en Agrolab Móstoles, espacio de agricultura urbana/periurbana situado en Móstoles, Madrid. Este entorno permite comprobar el funcionamiento del sistema en condiciones más próximas al uso previsto que las pruebas realizadas sobre mesa o en montaje controlado.

\textbf{Procedimiento.}
\begin{enumerate}
    \item instalar la estación en la zona de prueba autorizada;
    \item verificar alimentación, sensores, relé, bomba y conectividad LTE;
    \item iniciar el \textit{firmware} de estación y comprobar la lectura de sensores;
    \item publicar telemetría en el canal ThingSpeak correspondiente;
    \item comprobar la ingesta desde Raspberry Pi, el almacenamiento local y la visualización en \textit{dashboard};
    \item ejecutar una actuación de riego controlada;
    \item registrar fotografía del montaje y vídeo de funcionamiento como evidencia.
\end{enumerate}

\textbf{Criterios de aceptación.}
\begin{itemize}
    \item la estación obtiene lecturas coherentes de sensores;
    \item la telemetría aparece en ThingSpeak;
    \item la Raspberry Pi ingiere y almacena los datos;
    \item el dashboard muestra el estado actualizado;
    \item la bomba se activa únicamente durante el tiempo configurado;
    \item ante cualquier condición no verificable, la bomba permanece apagada.
\end{itemize}

\textbf{Evidencias.} La prueba se documenta mediante fotografía del montaje, vídeo de funcionamiento, capturas de ThingSpeak, capturas del \textit{dashboard} y registros de monitor serie. Las evidencias de monitor serie asociadas a la estación se recogen de forma específica en la Subsección~\ref{subsec:evidencias_monitor_serie_pruebas}.

\section{Conclusión}

El plan de pruebas de TierraViva permite validar el sistema de forma progresiva y controlada. La estrategia planteada comprueba por separado alimentación, sensores, comunicación, almacenamiento, API, \textit{dashboard} y actuación antes de ejecutar la integración completa.

Además, la relación entre riesgos y pruebas refuerza la calidad del proyecto, ya que cada punto crítico identificado dispone de una comprobación asociada. De este modo, la validación del prototipo contempla tanto el funcionamiento en condiciones normales como errores previsibles, situaciones de fallo y medidas de seguridad funcional.
